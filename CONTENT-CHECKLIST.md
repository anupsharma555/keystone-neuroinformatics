# Downstream Content and Asset Checklist

Use this checklist to complete the scaffold with real content, imagery, and publication-ready details.

## Core organization content

- [ ] Final homepage headline, subhead, and value proposition.
- [ ] Short organizational summary that is more specific than the current scaffold copy.
- [ ] Founder/team/advisor names, titles, and approved bios.
- [ ] Institutional affiliations or partner organizations, if public.
- [ ] Final contact language and preferred collaboration intake wording.

## Project content

- [ ] Public list of actual projects to publish first.
- [ ] For each project: title, summary, status, problem statement, approach, collaborators, next steps, contact CTA.
- [ ] For each project: approved canonical slug.
- [ ] For each project: any repository, publication, or external links.
- [ ] For each project: whether the page should remain public, indexable, or temporarily hidden.

## Research and blog-style updates

- [ ] Initial set of real research updates or project milestones to replace placeholder entries.
- [ ] For each update: title, publish date, summary, key insight, implications.
- [ ] Publication or preprint links where relevant.
- [ ] Decision on update cadence: occasional milestones vs. regular blog publishing.
- [ ] Voice/tone guidance for short updates, commentary, and publication summaries.

## Images and visual assets

- [ ] Logo files for web usage.
- [ ] Final favicon if different from the scaffold SVG.
- [ ] Default social preview image sized for link sharing.
- [ ] Hero visual or illustration that reflects neuroscience/data science work.
- [ ] Project-specific images, diagrams, or figures for pages that need visual context.
- [ ] Research-update thumbnails or figures where appropriate.
- [ ] Alt text and captions for every published image.
- [ ] Store approved assets in [src/assets/images](/Users/anup/gitProjects/keystone-neuroinformatics/src/assets/images).

## SEO and discoverability

- [ ] Final page titles and meta descriptions for all public routes.
- [ ] Organization details needed for richer structured data, such as official social profiles if any exist.
- [ ] Search Console submission after deploy.
- [ ] Review of `robots.txt`, `sitemap.xml`, and `llms.txt` after real content is added.
- [ ] Decision on whether additional pages should be indexed immediately or later.

## Collaboration workflow

- [ ] Final intake questions for collaboration requests.
- [ ] Decision on the next intake step: email only, form backend, CMS workflow, or AI-assisted triage.
- [ ] Consent/privacy language if visitor submissions will later be stored.
- [ ] Internal routing rules for who should review collaboration requests.

## Future AI integration

- [ ] Define whether future agents will only read public pages or also receive structured submissions.
- [ ] Decide whether project and collaboration data need a formal API or export format.
- [ ] Add machine-readable fields only when there is a clear downstream consumer.
- [ ] Review whether future private/internal agent workflows should stay separate from the public site.
